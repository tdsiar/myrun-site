What changed my thinking

September 12 · A debugging example

Find the first wrong result.

The text first changed at step 19. With AI guidance, I traced the problem to token selection.

I noticed that I had stored a decimal score in an integer. Truncation let a lower score win.

A wrong output does not mean every earlier stage is wrong.

Measure each stage.

One total could hide where the time went. I wanted separate timings.

Decide what a measurement means before using it to explain performance.

Check my understanding.

Some code worked before I could explain it. I challenged AI help that supplied answers I wanted to derive.

Running a command is different from knowing how to choose it.

Evidence and limits

What the test proves

On October 5, 2026, both programs exited successfully and produced identical 813-byte outputs.

The test used stories15M.bin, greedy generation, and a 256-step limit with early stopping.

Both builds used clang -O3 -Wall and -lm. Source files remained unchanged.

This checks one model and one starting condition. It does not establish correctness for other models or prompts.

The test does not establish a performance advantage. Memory cleanup and broader tests remain future work.
